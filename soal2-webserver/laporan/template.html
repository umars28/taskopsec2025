A.2 — Port SSH menjadi 2025

SOAL A.2

Konfigurasi ditulis sebagai drop-in /etc/ssh/sshd_config.d/01-sevima.conf. Penamaan 01- disengaja: sshd memakai aturan nilai pertama yang ditemukan yang dipakai, dan berkas drop-in dibaca berurutan secara abjad. Image cloud umumnya menyertakan 50-cloud-init.conf yang berisi PasswordAuthentication no; drop-in bernama 99- akan kalah oleh berkas tersebut dan login password menjadi mati tanpa terlihat.

Karena itu script tidak berhenti setelah menulis berkas, melainkan membaca kembali nilai efektif lewat sshd -T dan menolak melanjutkan bila port, PasswordAuthentication, atau PubkeyAuthentication tidak sesuai yang diminta.

Pada Ubuntu 22.10 ke atas, SSH memakai socket activation sehingga direktif Port di sshd_config diabaikan seluruhnya — port sebenarnya ditentukan ListenStream pada unit ssh.socket. Kondisi ini dideteksi dan ditangani dengan menulis override socket.

A.3 — Seluruh log aktivitas

SOAL A.3

Log dipasang berlapis: rsyslog untuk syslog klasik, journald dengan penyimpanan persisten agar log bertahan setelah reboot, auditd untuk jejak level syscall, perekaman input/output setiap sesi sudo, dan process accounting.

Aturan audit dibatasi pada auid>=1000 untuk execve, sehingga yang terekam adalah perintah yang dijalankan manusia, bukan aktivitas daemon sistem. Direktori /var/log sengaja tidak diawasi secara menyeluruh: watch semacam itu akan memicu event audit setiap kali auditd menulis lognya sendiri, menghasilkan umpan balik yang membanjiri disk. Yang diawasi adalah berkas konfigurasi lognya.

Rekaman sudo-io dipangkas otomatis lewat cron harian agar tidak tumbuh tanpa batas pada sistem dengan 1300 pemegang sudo.

A.4 — Penyesuaian sumber daya dengan ulimit

SOAL A.4

Batas disetel di dua tempat yang berbeda, karena keduanya tidak saling menggantikan. /etc/security/limits.d/ dibaca oleh pam_limits dan hanya berlaku pada sesi login. Layanan seperti nginx, apache2, dan haproxy dijalankan systemd tanpa melewati PAM, sehingga batasnya harus disetel lewat drop-in LimitNOFILE pada unit masing-masing. Kelalaian pada titik ini adalah penyebab paling umum limit terlihat sudah naik di shell tetapi tidak berlaku pada layanan.

Parameter kernel yang relevan untuk beban web dan load balancer disetel lewat /etc/sysctl.d/.

B — Certificate Authority

SOAL B

Root CA dibuat dengan OpenSSL pada direktori /root/ca, lengkap dengan database penerbitan (index.txt, serial) sehingga setiap sertifikat yang diterbitkan tercatat dan dapat ditelusuri. Sertifikat root menggunakan Country Code ID, Organization PT. Sentra Vidya Utama, dan Common Name SEVIMA CA sesuai ketentuan.

Empat sertifikat server diterbitkan untuk www, utara, timur, dan barat. Setiap sertifikat memuat subjectAltName; browser modern mengabaikan CN sepenuhnya dan hanya membaca SAN, sehingga sertifikat tanpa SAN akan selalu memicu peringatan betapapun benar CN-nya. Ini syarat langsung dari butir C.3.c dan D.4.

C.2 — timur.sevima.site (nginx)

SOAL C.a.2

Virtual host HTTP-only dilayani nginx pada port @@TIMUR_PORT@@, yaitu 81 disambung dengan ID peserta. Halaman menampilkan Hello World from Timur Site.

Catatan atas teks soal. Butir C.a.2.b menuliskan "X-Served-By: diisi dengan jenis web server (apache2)", padahal virtual host ini secara eksplisit diminta dilayani nginx pada kalimat sebelumnya. Teks (apache2) tampak tersalin dari butir C.a.1. Yang diikuti di sini adalah aturannya — "diisi dengan jenis web server" — sehingga nilainya @@TIMUR_SERVED_BY@@. Bila yang dimaksud penilai adalah teks literalnya, nilai ini dapat diubah lewat satu variabel konfigurasi tanpa mengubah bagian lain.

C.3 — barat.sevima.site (nginx, HTTPS)

SOAL C.a.3

Virtual host HTTPS dilayani nginx pada port @@BARAT_HTTPS_PORT@@, memakai sertifikat terbitan SEVIMA CA. Seluruh permintaan HTTP ke host ini diarahkan ke HTTPS dengan status 301, dilayani pada port @@BARAT_HTTP_PORT@@ karena port 80 dipegang HAProxy untuk butir D.

Syarat "dapat diakses tanpa peringatan apa pun" dipenuhi dengan memasang sertifikat CA ke trust store sistem, sehingga curl tanpa opsi -k berhasil memvalidasi rantai sertifikat. Untuk sisi laptop, sertifikat CA yang sama dipercayai secara manual.

Catatan atas HSTS. Header Strict-Transport-Security sengaja disetel dengan max-age pendek. HSTS berlaku per host dan mengabaikan nomor port: dengan nilai setahun, browser yang sekali membuka HTTPS host ini tidak akan pernah lagi mengirim permintaan HTTP polos ke host tersebut pada port mana pun, sehingga bukti redirect 301 tidak lagi dapat didemonstrasikan lewat browser.

D — Load Balancer HAProxy

SOAL D

HAProxy memegang port 80 dan 443. Permintaan ke www.sevima.site didistribusikan round-robin ke dua backend: utara (apache2) dan timur (nginx), sesuai ketentuan bahwa www.sevima.site dihosting oleh kedua host tersebut. Sertifikat frontend diterbitkan SEVIMA CA, dan akses dari localhost tervalidasi tanpa peringatan.

Bukti round-robin dibaca dari header X-Served-By: karena utara mengembalikan apache2 dan timur mengembalikan @@TIMUR_SERVED_BY@@, distribusi permintaan terlihat langsung dari sebaran nilai header pada sejumlah permintaan berurutan.

Header X-Forwarded-For yang datang dari klien dibuang lalu ditulis ulang dari alamat sumber sebenarnya, sehingga alamat klien tidak dapat dipalsukan. Di sisi backend, apache menggunakan mod_remoteip dan nginx menggunakan real_ip agar access log mencatat alamat klien asli, bukan alamat HAProxy.

Lampiran — Catatan keamanan

Soal meminta 1300 akun dengan password berpola w3bsite#1 sampai w3bsite#1300. Pola tersebut dapat ditebak sepenuhnya dari nama akunnya, dan seluruh akun memegang sudo. Ketentuan ini diimplementasikan apa adanya sesuai permintaan soal, dengan catatan bahwa pola semacam ini tidak layak dipakai di luar lingkungan penilaian.

Sebagai mitigasi yang tidak melanggar ketentuan soal, dipasang fail2ban dengan jail untuk sshd pada port 2025, pengerasan algoritma kripto dan batas sesi pada sshd, serta sejumlah parameter kernel pengerasan jaringan. Manifest kredensial disimpan dengan mode 0600 dan kunci privat pada direktori bermode 0700, keduanya di luar repositori.

Seluruh script, template konfigurasi, dan berkas verifikasi disertakan pada repositori taskopsec2025.
